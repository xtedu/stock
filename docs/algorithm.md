## 1. 先讲口径统一：为什么"当前 PE"不能直接用

这是所有估值类算法的地基，**不讲清楚后面会答不上来**。

**问题**：估值表 `valuation_daily` 存的是每天**收盘价对应的 PE**。盘中要判断"现在贵不贵"，但估值表里没有"此刻这个价对应的 PE"。

**做法**：用比例关系折算，而不是重算财报。

```
PE_now = P_now × PE_last / C_last
```

其中 `P_now` 是盘中快照价，`PE_last` / `C_last` 是估值表最后一条记录的 PE 与对应收盘价。
依据：TTM 口径下 PE 与价格成正比（`PE = 市值 / 净利润`，分母净利润在日内不变），所以价格按比例变，PE 同比例变。

代码：[`safety_zone._cur_pe_override`](../backend/app/services/safety_zone.py#L85-L96)；筛选侧同样处理见 [`screener.py`](../backend/app/services/screener.py#L147-L161)。

**讲解要点**
1. 为什么不能直接把最新 PE 拿来用 → 它是昨天的价算的，与今天的价不同口径，比出来的分位会失真。
2. 为什么不能重算净利润 → 财报只有季度数据，日内没有新净利润可算。
3. 这个折算的**假设**是什么、什么时候会失效 → 假设 TTM 净利润不变；财报发布当日净利润跳变，折算会滞后。

## 2. 优质股筛选算法（screener）

### 2.1 结构：两级漏斗

**硬门槛（一票否决）→ 加权打分（0-100 排名）**。不是把所有条件都塞进一个分数，而是先筛掉"不能碰的"，再对"能碰的"排序。

**硬门槛**（[`GATES`](../backend/app/services/screener.py#L27-L31)、判定逻辑 [L129-L142](../backend/app/services/screener.py#L129-L142)）：

| 门槛 | 阈值 | 含义 | 为什么 |
|---|---|---|---|
| 非 ST | 名称不含 `ST` | 排除特别处理股 | 退市风险股不参与价值投资 |
| 上市时间 | 日线条数 ≥ 750（≈3 年） | 排除次新股 | 需要完整经营周期样本 |
| ROE 均值 | 近 4 期 ≥ 10% | 盈利能力底线 | 长期 ROE 是质量第一指标 |
| 资产负债率 | 最新 ≤ 60% | 杠杆上限 | 高杠杆在利率/需求波动下易爆 |
| 扣非净利润 | 最新 > 0 | 主业不亏损 | 排除靠非经常性损益撑着的公司 |

### 2.2 打分：五因子加权

权重（[`WEIGHTS`](../backend/app/services/screener.py#L32-L33)）：

| 因子 | 权重 | 单项满分口径 | 归一化 |
|---|---|---|---|
| ROE 均值 | 35% | 20% | `min(100, ROE/20×100)` |
| 营收 3 年 CAGR | 15% | 30% | `min(100, CAGR/30×100)` |
| 净利 3 年 CAGR | 15% | 30% | 同上 |
| 现金流质量 OCF/NP | 15% | 100% | 直接用百分数 |
| PE 5 年分位（低者优） | 20% | — | `100 − 分位` |

```
Score = 0.35×S_roe + 0.15×S_rev + 0.15×S_profit + 0.15×S_cash + 0.20×S_pe
```

**归一化函数** `_cap(v, full) = clamp(v/full×100, 0, 100)`（[L36-L37](../backend/app/services/screener.py#L36-L37)）。
要点：**单项满分是"达标线"而非"上限"**——ROE 20% 就是满分 100，再高也不加分。这是"够好即可"而不是"越大越好"的打分哲学，避免极端值绑架总分。

### 2.3 CAGR 的合成：为什么要退化处理

代码 [`_cagr`](../backend/app/services/screener.py#L40-L50)。输入只有各期**同比增速** `y_i`（%），没有绝对值，所以要合成区间复合增速：

```
CAGR = ( ∏(1 + y_i/100) )^(1/n) − 1        （乘积 > 0 时）
CAGR = mean(y_i)                            （乘积 ≤ 0 时退化为算术平均）
```

**为什么要退化**：几何平均要求各期同比因子为正。一旦某期同比 ≤ −100%（或数据异常），`∏` 变成非正，开 n 次方没有实数意义，会算出 `nan` 或负增长假象。此时用算术平均作为"降级估计"。

**讲解要点（这里最容易被追问）**
1. 同比增速的连乘**不等于**真实复合增速的连乘——真实复合要用绝对值的比值。这里的做法是"用增长率反推复合"的近似，**必须主动说明这是个近似**。
2. 只取最近 3 期（[L163-L166](../backend/app/services/screener.py#L163-L166)）是为了"当前趋势"，但会**丢掉更早的高增长**，对已过高速期的公司会低估。

### 2.4 PE 分位：全历史经验分布，样本不足就弃权

代码 [`_pe_percentile`](../backend/app/services/screener.py#L59-L75)：

```
分位 = count(历史PE ≤ 当前PE) / N × 100     （取 ≤，即累计分布）
```

- 窗口：估值表全部有效记录（过滤 `PE > 0`），实际约 5 年。
- 样本门限：`N < 60` 直接返回 `None`，该因子**弃权**给中性分 50（[L176](../backend/app/services/screener.py#L176)）。
- 为什么用"≤ 计数"而不是插值：非参数、对分布形状不敏感，是分位数最朴素也最稳的定义。

**讲解要点**：分位低 ≠ 便宜。周期股在盈利顶点时 PE 很低（分母大），分位也会很低——这是**分母口径陷阱**，能主动指出会显得很懂。

### 2.5 三个数据工程细节（都是"脏数据适配"，值得单独讲）

1. **现金流质量自适应口径**（[L167-L172](../backend/app/services/screener.py#L167-L172)）：上游 `ocf_np_ratio` 有时是小数比率（0.9 = 90%），有时是百分数。判定 `均值 ≤ 2` 视为小数，`×100` 归一。这是一个**启发式魔数**，不是严谨做法——它的合理性来自"OCF/NP 极少低于 2 倍"这个业务常识。
2. **缺测值给中性分**：`pe` 缺失 → 50，`cash` 缺失 → 50。含义是"不知道"不比"好"或"坏"更差，避免因数据缺失误杀或误推。
3. **可解释性留痕**：分项得分与原始值全部写进 `reason` JSONB（[L181-L194](../backend/app/services/screener.py#L181-L194)），前端"得分档位/ROE/CAGR/PE分位"标签就是读它。**算法要能被追溯，不能只留一个总分。**

### 2.6 幂等与防御

- 每次筛选先把旧批次 `active=False`（[L92](../backend/app/services/screener.py#L92)），再写新批次 → 全池永远只有一批 active。
- 防御上限 200 只（[L196-L197](../backend/app/services/screener.py#L196-L197)）。
- 盘中/收盘两模式，结果用 `reason.source` 区分（[L183](../backend/app/services/screener.py#L183)）。

### 2.7 局限（被问到时主动说，得分点）

- 权重 35/15/15/15/20 是**经验赋值，没有回测支撑**（最大短板）。
- ROE 用"近 4 期均值"会**平滑掉下滑趋势**（均值掩盖拐点）。
- CAGR 用的是同比近似（见 2.3）。
- 分位窗口固定 5 年，长周期行业（地产/资源）会失真。

## 3. 安全区间算法（本项目最核心的算法）

### 3.1 先讲"为什么废弃了旧版"——这是最有讲头的部分

旧版叫**三法融合取交集**：技术支撑法、估值分位带、价格分位带各自给一个区间，然后

```
下沿 = max(各法下沿)， 上沿 = min(各法上沿)
```

**缺陷是结构性的，不是参数没调好**：

- 技术支撑法下沿 = `max(MA250, 布林下轨)`，它在数学上**天然 ≥ 250 日均线**（长期均线附近）；
- 价格分位带取的是近 5 年收盘价的 **15%~35% 分位**，上沿天然**低于** 250 日均线（长牛股尤其明显）。

于是 `下沿 > 上沿`，交集**恒为空**。实测 **96.5% 的股票**回退到"价格分位带"，上沿被压到历史低位区之外，产生大量不合理的"高于区间上沿，未到买点"结论。

**讲解要点**：交集法要求各方法**同一语义**（都是"便宜"）。技术支撑法是**趋势/位置**语义，价格分位带是**分布**语义，两者量纲意义不同却取交集 → 必然打架。**这是"语义不一致的集合运算"经典错误。**

### 3.2 现行算法：中枢锚定（center anchor）

代码 [`_calc_one`](../backend/app/services/safety_zone.py#L99-L150)，参数 [`L23-L25`](../backend/app/services/safety_zone.py#L23-L25)。

```
中枢  C = MA250 = (Σ 最近250日收盘价) / 250
基准区间 [0.90·C , 1.10·C]                     ← ZONE_LOW_RATIO / ZONE_HIGH_RATIO
若 PE 近5年分位 ≥ 70%：上沿压缩到中枢 → [0.90·C , C]   ← PE_HIGH_PCT
```

即：`zone_low = 0.9C`，`zone_high = 1.1C` 或 `C`。

**为什么以 MA250 为中枢**：250 日 ≈ 一年交易日，长周期均价≈企业中期价值中枢；均线越长，对短期消息越不敏感，适合当"锚"。

**为什么 ±10%**：给正常波动留缓冲，避免价格在中枢附近来回穿越导致结论反复。

**为什么 PE 高分位要压缩上沿**：MA250 只反映价格历史，不看估值贵贱。若估值已在 5 年高位（分位 ≥ 70%），说明"价格中枢本身可能就是被高估推上去的"，此时把上沿从 `1.1C` 压到 `C`，等于**要求回到中枢才谈得上安全**。这是"价格锚 + 估值约束"的双重把关。

### 3.3 三个带只做展示，不参与运算（关键设计决策）

| 带 | 公式 | 含义 |
|---|---|---|
| 估值隐含价格带 | `price × (P_k / PE_now)`，k = 10%、30% 分位 | "假如估值回到历史 10~30 分位，价格该是多少" |
| 价格分位带 | 近 5 年收盘价的 15%、35% 分位 | "历史上便宜区间在哪" |
| 预警线 | `MA20 − 2×σ20` | 布林下轨，深度低估参考 |

代码 [`_implied_band`](../backend/app/services/safety_zone.py#L37-L52)、[`_valuation_band`](../backend/app/services/safety_zone.py#L55-L74)（PE 带与 PB 带取交集，无交集退回 PE 带）、[`_price_band`](../backend/app/services/safety_zone.py#L77-L82)。

**为什么只展示**：3.1 的教训——参与取交集就会打架。改成"主算法给结论，辅助带给参考"，`detail` 字段并存（[L142-L147](../backend/app/services/safety_zone.py#L142-L147)）供人复核。

**讲解要点**：估值隐含带公式的推导是关键一题。设 `PE_now = P_now / E`（E 为每股收益），估值回到 `P_k` 时价格应为 `P' = P_k × E = P_k × P_now / PE_now`。即 `price × (P_k / PE_now)`。**E 在近似中视为不变**——这是它的假设边界。

### 3.4 预警线的统计含义

```
σ20 = 20 日收盘价标准差（日频，已实现波动率）
预警线 = MA20 − 2σ20
```

在近似正态假设下，落在 `±2σ` 之外的**单侧概率约 2.3%**。所以跌破预警线 ≈ "20 日窗口内的小概率极端下跌" → 用于标注"深度低估"（`detail.warn_line`）。它**不参与区间**，只在提醒文案里展示。

**讲解要点**：指出这是**简化正态假设**——股价分布尖峰厚尾，实际触发概率高于 2.3%；且 σ20 是**已实现波动率**，波动率聚集（GARCH 效应）会让"平稳期后突然放量"时预警线偏紧。

### 3.5 盘中模式：凭什么能用快照算

[L105-L112](../backend/app/services/safety_zone.py#L105-L112)：把当日快照价 `append` 到收盘序列尾部（**近似当作今日收盘**），使 `MA250` 的分子包含今日。同时 PE 用 1. 节的折算值。

**讲解要点（必问）**
1. 这样做 MA250 只被单日价格扰动 `1/250`，影响很小 → **安全**。
2. 但它**污染了序列**——所以只在内存里 append，**绝不写回正式日线**（呼应项目硬约束：快照只进 `intraday_spot` 表）。
3. 序列长度 `< 250` 直接返回 `None`（[L102-L103](../backend/app/services/safety_zone.py#L102-L103)）→ 不上架，而非给个凑合的区间。

### 3.6 幂等与健壮性

- 唯一约束 `(code, calc_date)`；同日重算**先删后插**（[L160-L161](../backend/app/services/safety_zone.py#L160-L161)），否则会唯一键冲突。
- 逐只 `try/except` 单独捕获（[L162-L167](../backend/app/services/safety_zone.py#L162-L167)），**单只异常不中断全池**。
- 结果带 `source`（intraday/official，[L147](../backend/app/services/safety_zone.py#L147)），收盘官方数据覆盖盘中。

### 3.7 局限与优化方向（这是本算法的诚实边界，讲出来很加分）

1. **本质是均线乖离率**：`(price − C)/C` 决定结论，而均线是**趋势指标不是估值指标**。所以它回答的是"离中期均价多远"，不是"便宜不便宜"。
2. **固定 ±10% 与个股波动率脱钩**：高波动股（如银行 vs 小盘题材）边界频繁穿越，结论易翻转。→ 应改为波动率自适应（如 `k×σ250`，k 由回测定）。
3. **低估区占比过高（实测 55.5%）**：一半以上的票被标"低估"→ 提醒疲劳，无法区分"真实低估"与"阴跌接刀"。
4. **无边界的滞回（hysteresis）**：价格在边界反复穿越时会反复触发状态翻转 → 应设"进入/退出"双阈值。
5. **PE 阈值 70% 是硬跳变**：分位 69.9% 与 70.1% 结论突然不同 → 应改为连续压缩曲线（如 `zone_high = C×(1+0.1×(1−分位/100))`）。
6. **缺趋势过滤**：均线下行时"低于下沿"可能是持续阴跌，需要叠加"均线走平/向上"或"价格不在下跌通道"的条件。

**优先级建议**：先做**历史回测验证**（否则所有参数都无法证伪）→ 波动率自适应带宽 → 趋势过滤 → 估值锚（中位数）替代 → PE 连续压缩。

## 4. 三态位置判定

代码 [`compare.build_metrics`](../backend/app/services/compare.py)（判定分支）：

```
price > zone_high            → above   高于上沿（等待回落）
zone_low ≤ price ≤ zone_high → in      区间内
price < zone_low             → below   低于下沿（低估区）
（现价或区间缺失）           → None    不判定
```

**为什么是三态不是两态**：两态只能分"能买/不能买"，会把"贵到不能接"和"跌穿到更便宜"混在一起——这是两种**完全相反的操作含义**。三态把"高位等回落"和"低位可关注"分开，前端用橙/绿/蓝三色区分。

**讲解要点**：判定用**区间几何位置**，不含趋势/资金观点——即"位置是位置，能不能买还要看后两个模块"。这是刻意分层，避免单一指标决定交易动作。

## 5. 资金流口径（money_flow）

**统计算法（东财口径，非本项目原创，必须讲清是引用口径）**：

东财把每笔成交按金额分档统计，定义为：

| 档位 | 单笔金额 | 含义 |
|---|---|---|
| 超大单 | ≥ 100 万元（或 ≥ 50 万股） | 机构/大户 |
| 大单 | 20 万 ~ 100 万元 | |
| 中单 | 4 万 ~ 20 万元 | |
| 小单 | < 4 万元 | 散户 |

```
主力净额 = 超大单净额 + 大单净额
净占比   = 该档净额 / 当日成交额 × 100%
```

**必须讲清的三个性质**
1. 这是**按成交金额推算的统计口径，不是真实席位数据**（Moreover 买卖方向靠成交价与买卖盘推断）。所以同一只股票，东财 / 同花顺 / 通达信的"主力净流入"**数值不同**。
2. **当日累计**：盘中取到的是"开盘至今累计值"，收盘后才是全天完整值 → 盘中和收盘的数值不可直接比大小。
3. 提取时统一 **元 → 万元** 再喂给大模型（[`llm._wan`](../backend/app/services/llm.py)），避免数量级误读。

**幂等优先级**：同一 `(code, trade_date)` 唯一，`official` 覆盖 `intraday`；且**盘中同步会检测当日是否已有 official，有则直接跳过**——防止盘中累计值污染收盘官方值。

## 6. 对比分析 + AI 定性研判

### 6.1 指标构建：保证"同日可比"

[`compare.build_metrics`](../backend/app/services/compare.py)：所有标的取**同一口径的现价与区间**（现价优先取比日线更新的快照），涨幅基准随来源切换：

```
现价来自盘中快照 → 基准 = 最新收盘价   （当日涨跌）
现价来自日线     → 基准 = 上一交易日收盘价
```

**讲解要点**：不做这一步就会出现"拿昨天的收盘比今天的盘中"的错位比较——**多标的对比的前提是同一时间切片**。

### 6.2 为什么不做"上涨概率"（本模块最重要的设计取舍）

大模型无法可靠预测次日涨跌。给一个百分数会产生**伪精确**（false precision）错觉。所以输出改成：

```
view        看多 / 中性 / 看空
reason      ≤60 字理由（引用具体指标）
support     支撑位
resistance  压力位
confidence  置信度 高/中/低
```

**讲解要点**：这不是"没做到"，而是**主动拒绝不可靠的输出形式**。可对比：若模型给"上涨概率 63%"，你无法验证 63% 的含义；但"看多 + 理由引用主力净流出"是可被复核的。

### 6.3 Prompt 工程三要点（[`llm.COMPARE_PROMPT`](../backend/app/services/llm.py)）

1. **表格化喂数**：`_format_table` 把 N 只股票转成"表头 + 每行一只"的定宽文本，模型对**表格化输入**的列对齐理解远好于散装 JSON。
2. **口径声明防幻觉**：提示词里明确写"资金流为推算口径、非席位数据""单位万元""‘-’ 表示缺失、不要据此判断"。不写这句，模型会把推算值当真值、把缺失值当 0。
3. **结构化输出约束**：要求"严格只输出 JSON，不要 markdown 代码块"，并给出 schema 示例。

### 6.4 解析鲁棒性

- [`_extract_json`](../backend/app/services/llm.py)：取首个 `{` 到末个 `}` 再 `json.loads`，兼容模型仍包了代码块/加了前后缀的情况。
- **白名单回填**：以本地算好的 `metrics` 为主循环，模型返回按 `code` 建索引回填（[`compare.analyze`](../backend/app/services/compare.py)）。模型漏答某只 → 该只结论为 `None`，**但指标不丢**。

**讲解要点**：这叫"**以本地数据为准，模型结果只做增强**"（fail-safe 设计）。反过来（以模型返回为准）会导致模型少答就丢股票、幻觉 code 就混入脏数据。

### 6.5 落库与可回看

`compare_analyses` 存 `codes / items（指标+结论）/ ai_summary`。注意 `items` 写 JSONB 时，`date` 类型需转 ISO 字符串（真实踩坑：直接写 `date` 对象会 `TypeError` 导致 500）。

### 6.6 局限

同一组输入多次调用，结论可能不完全一致（生成式模型固有方差）；`support/resistance` 是模型给的估计值，无回测校准。

## 7. 提醒触发算法

代码 [`monitor.check_and_notify`](../backend/app/services/monitor.py#L31-L86)。

```
命中条件：price < zone_low           （只在低估区触发）
价格来源：当日快照优先 → 否则最近收盘价
预警线：  detail.warn_line（缺失则回退 zone_low）
去重：    Redis key = alert:{code}:{date}，SET NX EX 86400
```

**三层去重（这是"幂等"的完整表达，值得单独讲）**

| 层 | 机制 | 防什么 |
|---|---|---|
| 数据库 | 唯一约束 | 重复数据落库 |
| 业务层 | 先删后插 / 覆盖写 | 同日重算不一致 |
| 提醒层 | Redis `SET NX + EX 86400` | 同一只股票当日重复推送 |

**讲解要点**：`SET NX`（不存在才写）是**原子操作**，天然防并发重复；`EX 86400` 让 key 次日自动失效，无需清理任务。这比"先查再写"更安全——后者在并发下有 TOCTOU 竞态。

## 10. 常见提问与回答要点

| 提问 | 回答要点 |
|---|---|
| 为什么用 MA250 不用 MA60/MA120？ | 250 是"年线"，对应一个完整经营周期；窗口越长越抗噪，但响应越慢——本质是"价值中枢"而非"交易信号" |
| ±10% 是怎么定的？ | 经验值，等价于"允许偏离中枢 10% 算合理"。**它的缺陷是与波动率脱钩**，应改自适应 |
| PE 分位 70% 为什么压到中枢而不是别处？ | 语义是"估值已在 5 年高位 → 不允许按 1.1 倍中枢买，必须回到中枢"。它是**开关**不是连续量，这是已知待优化点 |
| 交集为什么会空？ | 技术支撑法下沿 ≥ MA250，价格分位带上沿 < MA250 → 下沿恒大于上沿。是**结构性**问题 |
| 为什么不当成概率输出？ | 模型无预测能力，百分数是伪精确；改为定性 + 理由 + 点位，可复核 |
| 盘中价参与计算不怕污染数据吗？ | 只在内存 append，不写回日线；且单日影响 MA250 仅 1/250 |
| 数据缺失怎么办？ | 分项给中性分 50 而非 0；整段序列不足（<250）直接不上架，不给凑合结论 |
| 怎么保证不重复提醒？ | 三层幂等，提醒层用 Redis `SET NX + EX 86400` 原子去重 |
| 主力净流入能直接当买卖依据吗？ | 不能。它是按成交金额**推算**的口径，三家数据商数值不同，且盘中累计值不等于全天值 |

## 11. 已知局限汇总（诚实清单，建议放在最后一页）

1. 打分权重无回测支撑（**最需要补的短板**）。
2. 安全区间本质是均线乖离率，不是估值指标。
3. 固定带宽未适配波动率，边界易频繁穿越。
4. 低估区覆盖 55%+ 标的，提醒存在疲劳。
5. CAGR 用同比近似、ROE 用均值，均会掩盖趋势拐点。
6. PE 分位对周期股有"分母陷阱"。
7. AI 输出无概率校准，同输入多轮结果存在方差。
8. 资金流为推算口径、无逐笔历史。

**优化路线优先级**：历史回测 → 波动率自适应带宽 → 趋势过滤 → 估值锚（中位数）→ PE 连续压缩曲线。
